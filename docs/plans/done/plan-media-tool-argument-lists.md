# Pass argument lists to the built-in media tools

## Overview

A file whose path contains `$`, a backtick or `"` cannot be imported. `tools-zig` builds shell-style command strings for ImageMagick, ffmpeg and ffprobe with each path inside double quotes and no escaping (`magick "<path>" -resize ...`). `exec` hands the string to `in-process-tools.zig`, where `splitCommand` parses it back into words. `splitCommand` throws on `$` and backtick inside double quotes, and a `"` in a path ends the quoted word early. The runner the string ends up at (`InProcessRunner.run`) already takes the tool and an argument list. This plan first writes tests that import such files and watches them fail, then makes `tools-zig` build the argument list itself and call the runner through two new functions, `runTool` and `runToolLogged`, so no command string is built or parsed for the tools. It then removes `splitCommand`, `tryRun`, the `handles` field of `InProcessRunner` and node-utils' `exec.zig`, and checks that no other Zig code starts another process. Finally it removes the bug from `docs/investigations/media-tools-review.md` and updates the parts of that doc and `docs/mobile-native-media.md` that describe the string flow.
