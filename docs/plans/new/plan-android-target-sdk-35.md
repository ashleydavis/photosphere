# Raise the Android build to compileSdk/targetSdk 35

## Overview

A tester build installed through Firebase App Distribution is refused on a recent phone with Play Protect's "Unsafe app blocked: this app was built for an older version of Android and doesn't include the latest privacy protections". Play Protect shows that when an app's `targetSdkVersion` is more than two levels below the device's API level, and this app targets 33. The Pixel 6 plugged in here and every emulator in the pool report API 36 (Android 16), so on those devices anything below 34 is warned about, and a phone that has taken Android 17 (API 37, stable since June 2026) warns about anything below 35. Raising `targetSdkVersion` to 35 clears the warning on both, and stops short of 36, which would force edge-to-edge with no opt-out and is a bigger piece of work against Capacitor 5. Getting there means raising `compileSdkVersion` to 35 as well, which the current Android Gradle Plugin cannot do, and picking up the behaviour changes Android 14 and 15 apply to an app that targets them: foreground service type permissions, selected-photos access, and the six hour cap on a `dataSync` foreground service.

The app must keep building and passing every Android smoke test on the Pixel 6 and on the emulator pool, and `minSdkVersion` stays at 24, so nothing here drops an older device.

## Issues

## Steps

1. **Write the documentation.** Create `docs/android-sdk-levels.md` covering: which SDK levels the Android build uses (`minSdkVersion`, `compileSdkVersion`, `targetSdkVersion` in `apps/android-frontend/android/variables.gradle`) and why each is what it is; the Play Protect rule that a target more than two levels below the device's API level draws the "Unsafe app blocked" warning, and what that means for when the next bump is due; the toolchain the compile level pins (Android Gradle Plugin, Gradle wrapper, SDK platform and build-tools, all named with their versions); what targeting 34 and 35 required of the app (the `FOREGROUND_SERVICE_DATA_SYNC` permission, selected-photos access and how the app treats a partial grant, the `Service.onTimeout` requirement for a `dataSync` service, and the edge-to-edge opt-out); and what targeting 36 would additionally require, since the opt-out is ignored from 36 onwards. Update the two places in `docs/android-tester-distribution.md` that tell a tester to expect and work around the Play Protect warning (the "What this build is, and what it costs" bullet and the troubleshooting table row) so they describe the warning as something the target level no longer triggers, leaving debug signing as the remaining reason a phone may still object. Then STOP. Do not start step 2. Wait for the human to read the documentation and approve it, and if they revise it, revise the remaining steps here to match before writing any code.

2. **Raise the build toolchain.** In `apps/android-frontend/android/build.gradle` set the `com.android.tools.build:gradle` classpath to 8.6.0. In `apps/android-frontend/android/gradle/wrapper/gradle-wrapper.properties` set `distributionUrl` to Gradle 8.7 (AGP 8.6.0 requires Gradle 8.7 and JDK 17, and supports compileSdk up to 35). In `apps/android-frontend/scripts/install-android-sdk.sh` set `ANDROID_PLATFORM` to `platforms;android-35` and `ANDROID_BUILD_TOOLS` to `build-tools;35.0.0`, update `ANDROID_SYSTEM_IMAGE` to the API level the emulator pool actually runs (`system-images;android-36;google_apis;x86_64`), and rewrite the comment block above those values so it names the levels and the plugin version it is kept in step with. Run `bash apps/android-frontend/scripts/install-android-sdk.sh --install` to fetch the platform and build-tools this machine does not have, then `bash apps/android-frontend/scripts/install-android-sdk.sh --status` and confirm every package it lists is present. Leave `variables.gradle` alone in this step, so a failure here is the toolchain and nothing else. Complete when `bun run --filter=android-frontend test:unit` passes, which builds the app and runs the plain-JVM tests.

3. **Raise the SDK levels.** In `apps/android-frontend/android/variables.gradle` set `compileSdkVersion` and `targetSdkVersion` to 35, leaving `minSdkVersion` at 24. Build and read the result: run `bun run --filter=android-frontend test:unit`, then confirm the built APK reports the new level with `aapt dump badging` from the installed build-tools against `apps/android-frontend/android/app/build/outputs/apk/debug/app-debug.apk`. Expect the build to surface whatever AGP objects to in the Capacitor modules (both declare their own AGP classpath and the deprecated `compileSdkVersion` and `lintOptions` DSL); fix what it reports in this repository's own files, and if the objection is inside `node_modules/@capacitor`, stop and report it rather than editing a dependency.

4. **Declare the foreground service type permission.** In `apps/android-frontend/android/app/src/main/AndroidManifest.xml` add `android.permission.FOREGROUND_SERVICE_DATA_SYNC` beside the existing `FOREGROUND_SERVICE` permission, with a comment saying that an app targeting 34 or later must hold the permission matching each service's `foregroundServiceType` or `startForeground` throws a `SecurityException`. Complete when `bun run test:and -- 49` and `bun run test:and -- 50` pass, which are the tests that start the service.

5. **Stop the service when the platform times it out.** In `apps/android-frontend/android/app/src/main/java/au/com/codecapers/photosphere/jsengine/AutoImportService.java` override `onTimeout(int startId, int fgsType)` (added in API 35) so it logs that the platform has reached the six hour daily cap for a `dataSync` service and then runs the same shutdown the service already does for a stop, ending with `stopSelf()`. It has to be a thin shell over the existing stop path: the platform allows a few seconds before it throws `RemoteServiceException: a foreground service of type dataSync did not stop within its timeout`. Guard the override for the API level if the compiler requires it. This method takes Android types and cannot run under the plain-JVM unit tests, exactly as the rest of the service cannot, and the six hour cap cannot be forced from a test, so it gets no unit test and no smoke test of its own: say so in the plan report and in the code comment. Complete when the service's existing smoke tests (`bun run test:and -- 49`, `bun run test:and -- 50`) still pass.

6. **Handle selected-photos access in the native permission code.** In `apps/android-frontend/android/app/src/main/java/au/com/codecapers/photosphere/jsengine/MediaPermissions.java` add a `READ_MEDIA_VISUAL_USER_SELECTED` constant, a `FIRST_PARTIAL_MEDIA_VERSION` constant of 34, and a third alias constant for the API 34 and later permission list. Change `permissionsForVersion` to return the images, video and user-selected permissions on 34 and later, the two per-type ones on 33, and the legacy storage one below that. Change `aliasForVersion` to return the new alias on 34 and later. Add a function that classifies a grant into full, partial or none from the three individual grant results, returning a named enum or string constant set, because Capacitor's alias state is all-or-nothing and reports a partial grant as denied. Every one of these functions is plain Java and gets a unit test in `MediaPermissionsTest.java`.

7. **Report a partial grant through the plugin.** In `apps/android-frontend/android/app/src/main/java/au/com/codecapers/photosphere/jsengine/JsEnginePlugin.java` add the third `@Permission` alias for the API 34 and later list, and change `resolveMediaPermission` to read the three permissions individually, classify them with the function from step 6, and put both `granted` and a `partial` flag on the result. Declare `android.permission.READ_MEDIA_VISUAL_USER_SELECTED` in `AndroidManifest.xml` with a comment explaining that declaring it is what makes a partial grant persist instead of the app being run in the platform's compatibility mode, where the media permissions are granted for one session and taken away as soon as the app goes to the background.

8. **Treat a partial grant as not good enough for automatic import.** In `packages/mobile-frontend/src/lib/js-engine-plugin.ts` add `partial` to `IMediaPermissionResult`. In `packages/mobile-frontend/src/lib/mobile-media-permission.ts` add `"partial"` to `MediaPermissionState`, add a message constant telling the user that Photosphere can see only the photos they picked and that automatic import needs access to all of them, map the plugin's `partial` flag in `readPermissionState`, and return `enabled: false` with that message from `resolveMediaPermission`. The reasoning is the one already written into that file: a switch left in the on position while the app can see a handful of photos is a promise the app cannot keep. Unit tests for each changed function go in `packages/mobile-frontend/src/test/mobile-media-permission.test.ts`. iOS returns no `partial` flag, so its behaviour is unchanged; check `apps/ios-frontend` and `packages/mobile-frontend` for anything that switches on the state union and would now miss a case.

9. **Opt out of edge-to-edge enforcement.** In `apps/android-frontend/android/app/src/main/res/values/styles.xml` set `android:windowOptOutEdgeToEdgeEnforcement` to true on the themes the activity uses (`AppTheme`, `AppTheme.NoActionBar`, `AppTheme.NoActionBarLaunch`), with a comment saying that an app targeting 35 is drawn edge to edge by default, that Capacitor 5's WebView does not apply window insets, and that the opt-out is ignored from target 36 onwards so this is what the next bump has to replace. Verify by running `bun run stories:and` and reading the captured screenshots under `stories-screenshots/android/`: the app's own navbar must not sit under the status bar and no page content may sit under the navigation bar.

10. **Teach the smoke test harness about the third permission.** In `apps/smoke-tests/lib/android.sh` update `android_refuse_media_permission` to also revoke and mark user-fixed `android.permission.READ_MEDIA_VISUAL_USER_SELECTED` on API 34 and later, so a refusal is a refusal and not a partial grant left behind, and update `android_grant_media_permission`'s comment to say why granting the two per-type permissions is still a full grant. Add `android_grant_partial_media_permission`, which revokes the two per-type permissions and grants only the user-selected one, which is what the system leaves behind when a user picks "Select photos".

11. **Add the partial permission smoke test.** Create `apps/smoke-tests/tests/54-auto-import-partial-permission/test.sh`, modelled on `48-auto-import-no-permission`: reset the app state, launch, set up the partial grant with the new helper from step 10, switch automatic import on, and assert that the switch goes back off and the message about seeing only the picked photos is shown. Skip on iOS with a logged SKIP line and a reason, the way 47 and 48 do. Run it, then break it deliberately (make `resolveMediaPermission` return `enabled: true` for the partial state) and watch it fail before accepting it.

12. **Raise the API level the release workflow's emulator runs.** In `.github/workflows/release.yml` change the `api-level` passed to `reactivecircus/android-emulator-runner` from 33 to 35, so the job runs the smoke tests on a platform that applies the Android 14 and 15 behaviours this change adopts. Leave `arch` and `target` as they are. This cannot be run locally, so say plainly in the report that the workflow change is unverified until it runs.

13. **Update the documentation to match.** Revise `docs/android-sdk-levels.md` and `docs/android-tester-distribution.md` so they describe what was built, including anything that changed during implementation: the AGP and Gradle versions actually used, what the partial grant does in the app, the fact that the six hour foreground service cap has no automated coverage, and the emulator API level the release workflow now uses.

## Unit Tests

- `MediaPermissionsTest.java`: `permissionsForVersion` returns the images, video and user-selected permissions at 34 and above, the two per-type ones at 33, and the legacy storage one below 33.
- `MediaPermissionsTest.java`: `aliasForVersion` returns the new API 34 alias at 34 and above and the existing aliases below it.
- `MediaPermissionsTest.java`: the grant classifier returns full when the per-type permissions are granted, partial when only the user-selected one is, and none when nothing is, including the mixed cases (images without video, user-selected alongside one per-type permission).
- `packages/mobile-frontend/src/test/mobile-media-permission.test.ts`: `readPermissionState` returns `"partial"` for a result carrying the partial flag, and is unchanged for granted, denied, missing and malformed results.
- `packages/mobile-frontend/src/test/mobile-media-permission.test.ts`: `resolveMediaPermission("partial")` returns `enabled: false` with the partial message, and the other states are unchanged.

No unit test for `AutoImportService.onTimeout`, which takes Android types and cannot run under the plain-JVM test source set, in line with the rest of that service.

## Notes

- The Play Protect rule, from Google's developer guidance for Play Protect warnings, is that the warning appears when the target API level is more than two below the device's API level. Device API 36 warns below 34, device API 37 warns below 35. Target 35 covers both, and is due for another bump when Android 18 arrives.
- Target 36 was considered and rejected for now. Android 16 ignores `windowOptOutEdgeToEdgeEnforcement` for apps targeting 36, so it would mean making the shared React UI handle window insets on a Capacitor 5 WebView, which is a change to `packages/user-interface` affecting every platform. Better as its own piece of work than bundled into an install fix.
- Capacitor cannot move past 5 here, because the iOS side is fixed at macOS 12.7.6 and Xcode 14.2. Nothing in this plan touches Capacitor's version. The Capacitor Android modules read `compileSdkVersion`, `minSdkVersion` and `targetSdkVersion` from the root project's `ext`, so they follow `variables.gradle` without being edited.
- AGP 8.6.0 is the lowest plugin version that supports compileSdk 35. It needs Gradle 8.7 and JDK 17, and JDK 17 is what `apps/android-frontend/scripts/android-env.sh` already resolves, so the JDK does not move.
- The ImageMagick shim is already linked with `-Wl,-z,max-page-size=16384` and the FFmpegKit dependency is the 16KB-aligned fork, so 16KB page devices are covered for those. The prebuilt ImageMagick libraries fetched into `jniLibs` and the QuickJS AAR have not been checked for 16KB alignment here. That is a device-page-size question rather than a target level one, so it is out of scope, but it is the next thing to look at if the app installs on the Pixel 10 and then dies loading a native library.
- The emulator pool and the taps are the human's. Nothing in this plan brings the pool up, down or restarts it; the agent runs `bun run emu:and:pool:status` when it needs to know whether the pool is there, and `bun run --filter=android-frontend emu:pool:repair` only when no monitor holds `/tmp/photosphere-emulator-pool-monitor.lock`.
- Whether the Pixel 10 stops showing "Unsafe app blocked" can only be seen on that phone, through App Tester, and no automated check here can see it. Debug signing can draw the warning on its own on some phones, so if it survives this change, release signing is the next thing to look at, and that is a separate piece of work.
