# Remove global variables from the Zig port

## Overview

Global variables are not allowed in this repository unless the human explicitly asks for one. The Zig port of `psi` (`apps/cli-zig` and `packages-zig/*-zig`) holds mutable process-wide state in top-level `var` and `threadlocal var` declarations, and in `var` declarations inside struct bodies. This plan audits every one of them and removes them, moving each value into a struct that is created by whoever owns it (usually `main` in `apps/cli-zig/index.zig`) and passed down the call chain the way `allocator` and `io` already are. Many of these globals copy module-level state in the TypeScript original, so removing them makes the Zig code differ from the TypeScript in places; a comment in the Zig code says where.

Find every global with these commands. The audit below was taken from them on 2026-10-04.

- Top-level: `git ls-files 'apps/cli-zig/*.zig' 'packages-zig/*.zig' | grep -vE '/(test|tests)/|\.test\.zig$|/aws/|zlib-ng' | xargs grep -nE '^(pub )?(threadlocal )?var '`
- Inside struct bodies: the same file list, looking for an indented `var` whose nearest less-indented line opens a `struct {`, `union {` or `enum {`.

## Audit

Each entry gives: what the global holds, whether the TypeScript original has the same state, and how it is removed.

### Can be removed without passing anything new down

- `packages-zig/node-api-zig/src/lib/third-party/mime/index.zig` `defaultMime`, `defaultMimeState`: the mime table, built lazily on first use behind an atomic once-flag. TypeScript: the `mime` package's default export, built at load. Removal: build the table at compile time as a `std.StaticStringMap([]const u8)` with `initComptime`, lowercasing and skipping `*`-prefixed extensions in a comptime block, with the conflict check as `@compileError`. `mime()` stops returning an error.
- `packages-zig/tools-zig/src/lib/video.zig` struct-level `ffprobeCommand`, `ffmpegCommand`, `isInitialized`: only ever set to the defaults because `configure` was not ported. TypeScript: `private static` fields in `video.ts`. Removal: make both commands `const`; delete `isInitialized`, `initializeCommands` and its verbose log line.
- `packages-zig/storage-zig/src/lib/s3-client.zig` struct-level `SingleAttemptRetryStrategy.vtable`: a `var` only because the C field `aws_retry_strategy.vtable` is a non-const pointer. Zig-only. Removal: make it a field of the heap-allocated `SingleAttemptRetryStrategy` and point the C struct at `&self.vtable`.
- `packages-zig/vault-zig/src/lib/linux-keychain-vault.zig` and `windows-keychain-vault.zig` `toolChecked`: set once the tool check has run. TypeScript: module `let toolChecked` (the macOS TypeScript vault uses an instance field). Removal: copy `macos-keychain-vault.zig`, which already holds `toolChecked` as an instance field set in `init`; `checkTool` becomes a method.
- `packages-zig/storage-zig/src/lib/s3-client.zig` `interned_error_names`, `interned_error_names_mutex`: copies of S3 error codes kept for the life of the process because `errors.recordError` stores the error name slice without copying it. Zig-only. Removal: give `ErrorRecord` in `packages-zig/utils-zig/src/lib/errors.zig` a name buffer and copy the name in, as the message already is with `copyMessage`; do the same for `cause_names`. Delete `staticErrorName`.
- `packages-zig/storage-zig/src/lib/s3-client.zig` `last_http_status_code` (threadlocal): the HTTP status of the last S3 error on this thread. Zig-only (TypeScript reads `err.$metadata.httpStatusCode` off the error object). Removal: an `httpStatusCode` field on `ErrorRecord`, so the status travels with the error as it does in TypeScript. It then goes away with `last_error` below.
- `packages-zig/node-api-zig/src/lib/media-source-registry.zig` `mediaSourceBuilders`, `mediaSourceBuildersLock`: a map from source type to builder, filled at start-up. TypeScript: module `const mediaSourceBuilders = new Map`. Only `"folder"` is ever registered. Removal: a `const` table of `{ type, builder }` entries passed to `buildMediaSource`; delete `registerMediaSourceBuilder`, `clearMediaSourceBuilders` and both `registerFolderMediaSourceBuilder` functions.
- `packages-zig/api-zig/src/lib/media-source.zig` `lastDeleteErrorSourceIds` (threadlocal): the source ids of the last `MediaSourceDeleteError`, because a Zig error cannot carry them. Zig-only (TypeScript holds them in an instance field of the error). Removal: `IMediaSource.deleteItems` returns the ids it could not delete, allocated with the caller's allocator, empty on success; `runSourceCleanup` handles a non-empty list where it now checks `isInstance`. Delete `MediaSourceDeleteError`.

### Process start-up that moves into `main`

- `packages-zig/storage-zig/src/lib/s3-client.zig` `library_mutex`, `library_initialized`: guard the first call to `aws_s3_library_init`, whose own internal flag is not thread-safe. Zig-only. Removal: an `AwsSdk` struct created in `main` before any thread starts, calling `aws_s3_library_init` in `init` and `aws_s3_library_clean_up` in `deinit`; delete `initLibrary`. Unit tests that build a `CloudStorage` create one through a shared test helper.
- `packages-zig/lan-share-network-zig/src/lib/socket.zig` `winsockStarted`: set once `WSAStartup` has succeeded. Zig-only. Removal: a `Winsock` struct created in `main` on Windows (`WSAStartup` in `init`, `WSACleanup` in `deinit`); delete `ensureStarted`. Unit tests that open sockets on Windows create one.

### Values that move into a context passed down

These need an owner that every caller can reach. The owners are: a new `IAppContext` created in `main` and passed to `run`; `ICommandContext` (`apps/cli-zig/src/lib/init-cmd.zig`, built by `initContext`), which the commands already receive; and `ITaskContext` (`packages-zig/task-queue-zig/src/lib/types.zig`), which every task handler already receives on its worker thread.

- `apps/cli-zig/src/lib/process-argv.zig` `process_argv`: stands in for `process.argv`. Removal: `main` keeps argv and puts it in `IAppContext`; `configureLog`, `FileLogger.create`, `createDatabase` and `processColorEnvironment` take it as a parameter. Delete `process-argv.zig`.
- `packages-zig/node-utils-zig/src/lib/process-env.zig` `environ_map`: stands in for `process.env`. Zig 0.16 hands the environment to `main` as `init.environ_map`. Removal: put it in `IAppContext`, then `ICommandContext` and `ITaskContext`; every `getEnv`/`getEnvironMap` caller takes the map. Delete `setEnvironMap`.
- `apps/cli-zig/src/lib/log.zig` `fileLogger`: the active file logger. TypeScript: module `let fileLogger`. Removal: `configureLog` returns it; `initContext` stores it in a new `ICommandContext.fileLogger`; `cmd/add.zig` and `cmd/check.zig` read it from there. `encrypt`, `decrypt` and `bug` call `configureLog` themselves and keep the returned value.
- `packages-zig/task-queue-zig/src/lib/queue-backend.zig` `_backend`: the queue backend singleton. TypeScript: module `let _backend`. Removal: store the backend in `ICommandContext` and `ITaskContext`; `TaskQueue.init` takes it as a parameter. Delete `setQueueBackend`/`getQueueBackend`.
- `packages-zig/task-queue-zig/src/lib/worker.zig` `handlers`: the task handlers by type, filled at start-up. TypeScript: module `const handlers = new Map`. Removal: a `HandlerRegistry` owned by the worker pool (`apps/cli-zig/src/lib/worker-pool.zig`), filled by `initTaskHandlers(registry)`; `executeTaskHandler` takes the registry.
- `packages-zig/vault-zig/src/lib/get-vault.zig` `vaultInstances`, `vaultInstancesMutex`: the cache of vault instances by type. TypeScript: module `const vaultInstances = new Map`. Removal: a `VaultRegistry` with the map, an `Io.Mutex` and a `get(io, type)` method, created in `main`, carried in `IAppContext`, `ICommandContext` and `ITaskContext`; `getVault` callers in the CLI commands, `api-zig` LAN share and `node-api-zig/resolve-storage-credentials.zig` call `registry.get`. With a real `io` the spin lock goes.
- `packages-zig/vault-zig/src/lib/keychain-types.zig` `spawn_function`: a test-only hook that lets the macOS vault tests replace process spawning. Zig-only (TypeScript tests use `jest.spyOn`). Removal: see the open question in Notes; until the human answers, this step is not taken.
- `packages-zig/node-api-zig/src/lib/hash-cache.zig` `loadedHashCaches` (threadlocal): read-only hash caches per directory, kept per worker so a second reader does not read the file again. TypeScript: module `const loadedHashCaches`, one per worker. Removal: a `LoadedHashCaches` struct with `load(io, cacheDir)` and `deinit`, owned by `IWorkerState` in `worker-pool.zig` and reached through a new `ITaskContext` field (an interface, since task-queue-zig does not depend on node-api-zig).
- `packages-zig/tools-zig/src/lib/image.zig` struct-level `convertCommand`, `identifyCommand`, `isInitialized`, `imageMagickType`: the ImageMagick commands found once at first use. `isInitialized` is a plain bool written from worker threads, so it is a data race today. TypeScript: `private static` fields in `image.ts`. Removal: an `ImageMagick` struct with these fields, created once in `initContext` and carried in `ICommandContext` and `ITaskContext`; `Image.init` takes it, and `verifyImageMagick`, `getImageMagickType` and `resetInitialization` become its methods (tests build their own instead of resetting).
- `apps/cli-zig/src/lib/picocolors.zig` `detected_support`, `support_override`: cached colour detection, and a test override. TypeScript: module state inside the `picocolors` package; the override is Zig-only. The lazy write is a data race if a worker thread formats a coloured string. Removal: compute a `Colors` value once in `main`, carry it in `IAppContext` and `ICommandContext`, and replace `pc.x(allocator, text)` calls with `colors.x(allocator, text)`. Tests build `createColors(true)` or `createColors(false)` instead of calling `setColorSupportOverride`, which is deleted.
- `apps/cli-zig/src/lib/clack/prompts/common.zig` `stdin_buffer`, `stdin_reader`, `stdin_input`, `stdout_buffer`, `stdout_writer`: the stdin reader and stdout writer shared by every prompt. TypeScript: Node's global `process.stdin`/`process.stdout`. Removal: create them once in `main` (buffers on `main`'s stack) and carry pointers in `IAppContext`; `resolveInput`/`resolveOutput` take them, and the prompt functions and the two direct callers (`cmd/list.zig`, `cmd/secrets.zig`) pass them.
- `packages-zig/utils-zig/src/lib/console.zig` `stdout_mutex`, `captured_stdout`, `captured_stderr`: a lock on stdout and a test capture. Zig-only (stands in for `console`). Removal: a `Console` struct holding the writers and the lock, created in `main`; `ConsoleLog` holds a `*Console`; the direct `console.*` callers take it. Tests build a `Console` with their own writers instead of calling `setCapture`, which is deleted.
- `packages-zig/utils-zig/src/lib/log.zig` `console_log`, `pub var log`: the global log, and every file's `const log = &utils.log.log`. TypeScript: `export let log`. Removal: an `ILog` in `IAppContext`, `ICommandContext` and `ITaskContext`; `configureLog` returns the log instead of calling `setLog`, and every function that logs takes the log from its context or as a parameter. Delete `setLog`.
- `apps/cli-zig/src/lib/worker-log-bun.zig` `workerLogInstance` (threadlocal), `main_log`, `routing_log_state`: route the global log to the calling worker's log. `workerLogInstance` copies TypeScript's `let workerLogInstance`; the other two are Zig-only. Removal: once the log is passed down, each worker task gets its own log in `ITaskContext.log` and the routing log and all three globals are deleted. `setWorkerTaskId` takes the worker's `*WorkerLogBun`, which `workerMain` already owns.
- `packages-zig/utils-zig/src/lib/errors.zig` `last_error` (threadlocal): the message, name and cause chain of the last error thrown on this thread, because a Zig error cannot carry a message. Zig-only. Removal: a caller-owned `Diagnostics` struct (what `ErrorRecord` holds now), passed to every function that can fail with `error.Thrown`. `throwError` and its siblings become `diag.fail(...)`-style methods returning `error.Thrown`, and the readers (`lastErrorMessage`, `errorMessage`, `errorName` and the cause readers) read from the `Diagnostics` they are given. Each worker task owns its own `Diagnostics`, so `captureError`/`restoreError` are deleted and the joining thread reads the task's. This is the largest change: every fallible function in the port gains a parameter.

### Signal handling: cannot be removed completely

- `packages-zig/node-utils-zig/src/lib/termination.zig` `terminationCallbacksInitialized`, `terminationCallbacks`, `pendingSignal`, `signalIo`, `signalPipe`, `signalEvent`; and `apps/cli-zig/src/lib/process-signals.zig` `registrations`, `registrationCount`, `listenersLock`, `pendingSignals`, `watcherStarted`, `wakePipe`. Both files install their own SIGINT/SIGTERM handler, self-pipe, watcher thread and Windows `SetConsoleCtrlHandler`. TypeScript: `terminationCallbacks` and `terminationCallbacksInitialized` copy `termination.ts`; the rest stands in for Node's single `process.on`/`process.removeListener` emitter.
- Bug found by the audit, from reading the code (not yet shown by a test): `process-signals.zig` restores `SIG_DFL` when its last listener is removed, which removes `termination.zig`'s handler too. After a spinner, `dbs` or `secrets` listener is removed, Ctrl+C kills the process without running the termination callbacks.
- Why some state must stay: a POSIX `sigaction` handler receives only the signal number (or `siginfo_t*` and `ucontext*`), and a Windows `HandlerRoutine` receives only a `DWORD`. Neither can be given a pointer to state, so the handler can only reach state through a global.
- Removal: merge both files into one `SignalDispatcher` created in `main` and carried in `IAppContext` and `ICommandContext`. It holds the listener table, the termination callbacks, the `Io`, the read end of the pipe and the watcher thread (which gets the dispatcher as its spawn argument). Termination's shutdown is one default listener. `on`, `removeListener`, `registerTerminationCallback`, `exit` and `shutdownOnUncaughtException` take the dispatcher. What must remain is one global pointer, set before the handler is installed, to the few fields the handler touches (the pending signal bits, the pipe's write end, the Windows event). Adding it needs the human's approval (see Notes).

## Notes

- Open question, signals: a signal handler can only reach state through a global, so removing the signal globals leaves one global pointer. Under `CLAUDE.md` it needs the human's explicit approval. Step 21 is not taken until the human says whether to add it.
- Open question, `spawn_function`: it is a test-only hook already in shipped code, and its own comment says it is pending approval. Replacing it with a per-instance spawn function passed to `MacOSKeychainVault.init` is still a test-only injection point in shipped code, which `CLAUDE.md` says the human must approve. The other choice is to drop the hook and test the macOS vault against the real `security` tool. Step 22 is not taken until the human picks one.
- Not checked by the audit: whether any `pc.x` default colour call runs on a worker thread, and whether every `exit(io, ...)` call is `termination.exit`.
- Removing the globals means the Zig code no longer copies TypeScript module state in many files. That is the intended result, and step 24 records it in the port map.
- Steps 19 and 20 touch nearly every file in the port. They are last among the context steps so the earlier ones land on a stable base.
