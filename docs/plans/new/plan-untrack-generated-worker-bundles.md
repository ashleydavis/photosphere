# Untrack the generated mobile worker bundles

## Overview

Three copies of the generated mobile worker bundle are committed to git: `packages/mobile-worker/worker.bundle.js` (the build output) and its two copies in the native projects, `apps/android-frontend/android/app/src/main/assets/worker.bundle.js` and `apps/ios-frontend/ios/App/App/worker.bundle.js`. Each is about 2.6 MB, they are byte-identical, and every edit under `packages/mobile-worker/src/` rewrites all three, so they dominate the repo's churn and diffs. They are pure build output of `bun bundle.ts` (`build:bundle`) plus a `cp` (`copy:bundle`). This plan removes all three from git tracking, adds `.gitignore` entries so they cannot be re-added, and closes the two build paths that currently rely on the files being present at checkout (`bun run build:and` and `bun run build:ios`, which invoke Gradle/Xcode directly without running `sync`). Every other build path already regenerates the bundle: both mobile `sync` scripts run `bundle:worker` before `cap sync`, and every mobile job in `.github/workflows/release.yml` goes through `sync`, so the release workflow needs no change.

## Issues

## Steps

1. **Untrack the three bundle files.** Run `git rm --cached packages/mobile-worker/worker.bundle.js apps/android-frontend/android/app/src/main/assets/worker.bundle.js apps/ios-frontend/ios/App/App/worker.bundle.js`. Use `--cached` only, never a plain `git rm`: the working-tree copies must stay so the currently checked-out tree can still build. Do not commit; leave the change staged for the developer to review. Confirm with `git ls-files | grep worker.bundle.js` returning nothing and `ls` showing all three files still on disk.

2. **Ignore the build output in the root `.gitignore`.** Add a commented entry near the other build-output entries for `packages/mobile-worker/worker.bundle.js`. Comment: generated by `bun --filter=mobile-worker build:bundle`, never committed.

3. **Ignore the Android copy.** In `apps/android-frontend/.gitignore`, add `android/app/src/main/assets/worker.bundle.js` to the existing "Android generated build outputs" block, with a comment saying it is copied in by `bundle:worker` (which `sync` runs) and is never committed. Do not touch `apps/android-frontend/android/.gitignore` (that file is the Capacitor/Android template and the path is cleaner to express from the frontend root).

4. **Ignore the iOS copy.** In `apps/ios-frontend/.gitignore`, add `ios/App/App/worker.bundle.js` to the existing "iOS generated build outputs" block, with the same style of comment.

5. **Verify the ignore rules actually apply.** Run `git check-ignore -v` against all three paths and confirm each is matched by the intended rule, and run `git status --porcelain` and confirm none of the three appears as untracked. `.gitignore` has no effect on tracked files, so this step must come after step 1.

6. **Make `bun run build:and` regenerate the bundle.** In the root `package.json`, change the `build:and` script to run `bun run --filter=android-frontend sync` before `cd ./apps/android-frontend/android && ./gradlew :app:assembleDebug`. Without this, a fresh clone that runs `build:and` produces an APK with no `worker.bundle.js` asset, and every background task fails at runtime.

7. **Make `bun run build:ios` regenerate the bundle.** In the root `package.json`, change the `build:ios` script to run `bun run --filter=ios-frontend sync` before the existing `xcodebuild` invocation. Without this, `xcodebuild` fails outright, because `apps/ios-frontend/ios/App/App.xcodeproj/project.pbxproj` lists `worker.bundle.js` in the App target's Resources build phase and a missing build input is a hard Xcode error.

8. **Add a fail-fast Gradle guard for the Android asset.** In `apps/android-frontend/android/app/build.gradle`, register a `checkWorkerBundle` task that checks `src/main/assets/worker.bundle.js` exists in its `doLast` block and throws a `GradleException` naming the missing path and telling the developer to run `bun run bundle:worker` from `apps/android-frontend`. Wire it with `preBuild.dependsOn checkWorkerBundle`. The check must run at execution time, not configuration time, so an Android Studio Gradle sync is unaffected. This closes the only silent failure mode: Gradle happily builds an APK with a missing asset, unlike Xcode, which fails the build.

9. **Make the mobile `clean` scripts remove the copied bundle.** In `apps/android-frontend/package.json`, extend `clean` to also `rm -f android/app/src/main/assets/worker.bundle.js`. In `apps/ios-frontend/package.json`, extend `clean` to also `rm -f ios/App/App/worker.bundle.js`. `packages/mobile-worker`'s `clean` already deletes `worker.bundle.js`; previously that deleted a tracked file, now it is a plain build-output clean.

10. **Add a wiring regression test.** Create `packages/mobile-worker/src/test/bundle-wiring.test.ts`. It reads the repo files with `node:fs` (paths resolved relative to the test file) and asserts: (a) `packages/mobile-worker/worker.bundle.js` appears in the root `.gitignore`; (b) `android/app/src/main/assets/worker.bundle.js` appears in `apps/android-frontend/.gitignore`; (c) `ios/App/App/worker.bundle.js` appears in `apps/ios-frontend/.gitignore`; (d) the `sync` script in each mobile app's `package.json` runs `bundle:worker` before `cap sync`; (e) the root `package.json` `build:and` and `build:ios` scripts both run a `sync` before invoking `gradlew`/`xcodebuild`. This is the automated guard that the bundles cannot be silently re-tracked and that no future edit drops the regeneration step. Use `test(` (not `it(`) per the project style.

11. **Update the two native-function guides.** In `docs/adding-android-native-functions.md` and `docs/adding-ios-native-functions.md`, replace the sentence "The worker JS is shipped as a prebuilt file." with wording stating the worker JS is generated at build time and is not committed: `bun run sync` (and therefore `bun run open`, `run`, `test:and`/`test:ios`, and the story player) regenerates and copies it, and `bun run bundle:worker` does just the bundle step after editing `packages/mobile-worker/src/`.

12. **Note the generated status in the background-tasks doc.** In `docs/background-tasks.md`, in the paragraph that describes `worker.bundle.js` being compiled from the `*.worker.ts` handlers, add one sentence: the bundle is a build artifact produced by `packages/mobile-worker/bundle.ts`, copied into both native projects by `copy:bundle`, and is not committed to git.

13. **Regenerate and confirm a clean tree.** Delete all three files, run `bun --filter=mobile-worker build:bundle` then `bun --filter=mobile-worker copy:bundle`, and confirm all three reappear and that `git status --porcelain` reports no changes for them (proving the ignore rules hold for freshly generated files).

## Unit Tests

- `packages/mobile-worker/src/test/bundle-wiring.test.ts` (new): the assertions listed in step 10. No production TypeScript function is added or changed by this plan (the changes are `.gitignore` entries, `package.json` scripts, a Gradle task, and docs), so this hygiene test is the only unit test required.

## Smoke Tests

- Existing `bun run test:and` (Android smoke suite): `android_build` in `apps/smoke-tests/lib/android.sh` runs `bun run sync`, which runs `bundle:worker`, so the suite proves the bundle is generated, copied, packaged, and executed by QuickJS from a tree with no committed bundle. Any import/scan task in the suite exercises the engine.
- Existing `bun run test:ios` (iOS smoke suite): `ios_build` in `apps/smoke-tests/lib/ios.sh` runs `bun run sync` before `xcodebuild`, giving the same proof for JavaScriptCore, including that the Resources build phase finds the regenerated file.
- Existing `bun run test:and:unit` and `bun run test:ios:unit`: both run the mobile `sync` first, so they also cover regeneration. `apps/ios-frontend/ios/App/AppTests/WorkerBundleParityTests.swift` loads the regenerated bundle into a `JSContext`.
- Manual-equivalent automated check for the new Gradle guard (only where the Android SDK is available): delete `apps/android-frontend/android/app/src/main/assets/worker.bundle.js`, run `bash apps/android-frontend/scripts/android-gradle.sh :app:preBuild`, and confirm it fails with the `checkWorkerBundle` message; then run `bun run --filter=android-frontend bundle:worker` and confirm `:app:preBuild` passes. If no Android SDK is present on the machine, record that this check was not run and rely on the CI Android jobs.

## Verify

- `git ls-files | grep worker.bundle.js` prints nothing.
- `git check-ignore -v` matches a rule for each of the three paths.
- All three files still exist on disk after step 1 and `git status --porcelain` does not list them.
- `bun --filter=mobile-worker build:bundle && bun --filter=mobile-worker copy:bundle` regenerates all three from an empty state and leaves `git status` clean.
- `bun run compile` succeeds across the monorepo.
- `bun run test` passes, including the new `bundle-wiring.test.ts`.
- `bun run test:all` passes (CLI and Electron smoke suites; unaffected by this change but must not regress).
- Grep `.github/workflows/release.yml` for `gradlew`, `xcodebuild`, `test:and`, `test:ios`, `stories:and`, `stories:ios` and confirm every mobile job reaches the native build through a `sync`, so no workflow step needs the committed bundle.
- Mobile smoke suites (`bun run test:and`, `bun run test:ios`) pass on a machine with an emulator/simulator, or are confirmed green in CI.

## Notes

- Files removed from tracking, with sizes: `packages/mobile-worker/worker.bundle.js`, `apps/android-frontend/android/app/src/main/assets/worker.bundle.js`, `apps/ios-frontend/ios/App/App/worker.bundle.js`, each about 2.6 MB, byte-identical, all produced by `build:bundle` + `copy:bundle`.
- No other generated artifact is tracked. A scan of the largest tracked files shows only test fixtures (`test/dbs/**`, `test/*.jpg|mp4|zip`), `bun.lock`, and `apps/android-frontend/android/gradle/wrapper/gradle-wrapper.jar` (the standard Gradle wrapper, which is meant to be committed). The vendored mobile ImageMagick/ffmpeg artifacts are already ignored via `android/app/src/main/jniLibs/`, `android/.media-fetch/`, and `ios/App/vendor/`.
- Build paths audited and already safe (all run `bundle:worker` via `sync`): `apps/android-frontend` and `apps/ios-frontend` `sync`/`open`/`run`/`test:unit`; `android_build`/`ios_build` in `apps/smoke-tests/lib/`, used by both the mobile smoke suites and `scripts/story-player.sh`; root `test:and`, `test:ios`, `test:and:unit`, `test:ios:unit`, `stories:and`, `stories:ios`.
- Build paths that were unsafe and are fixed by steps 6 to 8: root `build:and` (Gradle silently packages an APK without the asset, so the guard in step 8 is what makes it loud) and root `build:ios` (Xcode fails on the missing Resources build input).
- Rewriting git history to purge the bundles from past commits is deliberately out of scope. It does not change the working tree, it would require a force-push and break every existing clone, and the repository history is not the problem being solved. The change only stops future churn.
- After this change is committed and pushed, anyone who pulls it has the three files deleted from their working tree (git removes files whose deletion is recorded in the commit). They must run `bun run sync` (or `bun run bundle:worker`) in `apps/android-frontend` or `apps/ios-frontend` before their next native build. Worth mentioning in the commit message.
- `docs/plans/done/**` contains statements such as "Rebuild and commit `worker.bundle.js` for both platforms since the bundle is checked in". Those are historical records of completed work and are deliberately left untouched; only the live guides in `docs/` are updated.
